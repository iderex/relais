# docs/decisions

One decision per file, written before the thing it constrains exists, in the
present tense, saying what was decided, why, what it costs and what would reverse
it. A record here is the authority a later change is argued against: where the
code and a record disagree, the record is what has to be changed first, in its
own pull request, with the reason. What does not belong here is a description of
how something currently works, because that drifts against the thing it describes
and belongs next to the code, and a decision nobody has actually made, because a
record that reads as settled when it is not is worse than no record. Where a
decision is the maintainer's rather than the plan's, it stays an open entry in
issue #1 and no record here assumes an answer to it.
